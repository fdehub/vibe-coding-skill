# 使用指南

本技能以Codex为目标宿主，入口是[vibe-coding/SKILL.md](../vibe-coding/SKILL.md)。安装方法见[README](../README.md)。

## 让AI引导需求

```text
使用 $vibe-coding。我有个做个人工具的想法，但不知道怎么描述，请一步步引导我。
```

预期先讨论用途和核心体验，再补会影响方案的选择；普通技术细节交给执行者决定。你也可以明确委托“其余你定，先给一版建议”。

## 只要开发提示词

```text
使用 $vibe-coding。帮我写一个个人待办网页的开发提示词：支持新增、完成、筛选、本地保存，手机可用。只要提示词，暂不开发。
```

需求足够明确时，直接交付具体行为、边界和验收条件。只要提示词意味着当前助手只交付文本，提示词内部可以要求下游开发AI实现代码。

## 直接实现或修复

先打开需要修改的目标项目目录，再说明需求：

```text
使用 $vibe-coding。请在当前项目实现这份需求，沿用现有技术栈，完成后运行相关检查，给出可查看结果：
【需求】
```

```text
使用 $vibe-coding。保存时提示成功，但刷新后记录消失。请定位原因并修复，验证保存和刷新流程，保留其他行为。
```

## 继续上次的工作

```text
使用 $vibe-coding。先核对已有进度记录与实际代码，再继续尚未完成的工作。
```

长任务按需保存决定、进度、验证及下一步；简单任务不强制创建管理文件。

## 其他AI工具

`$vibe-coding`是本文的Codex调用方式。其他工具按其支持的技能机制加载；能读取项目文件时也可发送：

```text
请读取当前仓库的 vibe-coding/SKILL.md，按需读取其中引用的参考文件，再处理下面的请求：
【填写需求，并说明只要提示词还是直接实现】
```

如果对方不能访问本机路径，需提供完整技能目录，保留相对路径。跨宿主适配尚未验证。

## 交付边界

用户选择、建议默认值与待核实事实应分开。只改一段时保留其他已确认要求。修改显示名称时保留未要求变更的存储契约；实际项目缺少必要条件时明确未验证项。

技能是工作指引，不是结果保证。[验证摘要](../validation/README.md)说明已测范围与限制。
