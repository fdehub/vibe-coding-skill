# 项目上下文与交接

在跨会话、任务较长、存在多项依赖／决策，或用户明确需要交接时使用。简单修改保留在对话与变更说明中即可。

## 维护最少的可恢复状态

优先更新工程已经使用的需求、计划或进度文件；没有现成位置且确实需要落盘时，可在本项目 `docs/vibe-coding/` 下建立一份 `state.md`。该路径只是默认建议，不覆盖既有约定。

状态只记录下一次恢复所需的信息：

- 本轮目标、范围和明确非目标。
- 已确认的业务决定与必要理由；普通实现选择简记即可。
- 当前工程入口、相关文件、运行和验证命令。
- 各任务的实际状态：未做／在做／完成／依赖阻塞。
- 关键证据及其位置，包括失败检查与未验证事项。
- 下一步及其前置依赖；尚未决定的问题不冒充已确认需求。

引用现有文件与契约，不复制整份需求、聊天或日志。只保存任务相关内容，不写入密钥或个人敏感信息。多个任务各有明确记录位置，避免覆盖另一项工作的进度。

## 恢复时先核对实际工程

读取当前任务的记录、适用工程说明和相关文件，查看工作区差异；若有 Git，核对分支及必要提交信息。记录代表过去的观察，不一定代表现在的代码。

出现矛盾时依据当前文件、运行结果及用户最新选择修正记录。不要因为“状态写着已完成”就跳过缺失的实现，也不要重复执行此前可能已成功的外部操作。核对后从尚未完成且依赖满足的任务继续，不重新从头访谈。

## 用户要求交接时

给下一位执行者一段可以直接使用的说明：目标与当前状态、应先读取的文件、已确认决定、已做变更、实际验证及未解决问题、下一步命令或行动。保留关键限制和既有授权范围；交接文本不能扩大权限。

如果用户没有指定交接文件位置，沿用已有项目记录；没有现成位置时，将需跨会话保留的交接文件写入本项目 `docs/vibe-coding/`，给出绝对路径。系统临时目录只用于可丢弃的中间材料。交接本身无需创建外部工单、发送消息或读取其他聊天历史。
