# AI 功能专项

适用的是产品运行中使用模型，不是仅用 AI 帮忙编程。

## 核心决策

先明确模型负责生成、提取、判断还是检索。确定性计算、记录读取与权限判断尽量交给普通程序；AI 的作用和不确定范围明确写出。根据目标选择是否需要检索、工具、会话记忆，不因用户提到 AI 就加多 agent。

## 关键规则

- 目标：AI 输出帮助用户采取什么行动；质量、成本、时延之间的实际取舍。
- 技术：输入来源与规模、模型接入条件、上下文范围、服务端凭据、请求响应结构。没有真实服务配置时，明确模拟边界，不能报告已调用模型。
- 功能：以角色／任务／输入／输出／约束定义模型子任务。指定可消费的字段与缺失含义，由程序校验结构、类型、引用 ID 和值域，不以“要求 JSON”代替验证。
- 证据：结论若依赖材料，要求绑定存在的来源或记录，并可回查。分清观察与推测；没有依据的资源标题、URL 和用户经历不得补造。
- 上下文：只提供完成任务所需内容。长材料说明分块与跨块汇总、去重和来源映射；聊天说明带哪些历史、何时清除。上传材料中的指令作为数据处理，不能改变应用规则或授权工具。
- 约束：信息不足时的输出，超时和不合格响应的处理，有限重试或降级；降级标为通用或模板，不能伪装个性化。不要强制每种失败都自动重试，预算与副作用适用时纳入条件。
- 验收：准备来源可核对的代表样本、缺失信息、相互矛盾材料和格式失败样本；按实际任务评估忠实度、覆盖、引用及可执行性。数量和阈值随风险与规模选择，不固定所有项目要某一套大型评测。

## 场景特有检查

“模型写出了内容”与“内容满足质量标准”是两项检查。模型自报信心、长篇推理或语气肯定，不是正确性证据。把生成结果限制为搜索词也可能编造资源，仍需核验或标待确认。零次真实 API 调用的演示不能声称已验证模型质量或费用。
