# 工作流与自动化专项

## 核心决策

区分一次同步请求、长任务与跨系统多步动作。核心是步骤之间的数据和状态如何流转，以及失败后会不会重复产生外部结果；不强制使用某个低代码平台。

## 关键规则

- 目标：谁在什么条件下触发，节省哪个重复过程，最终需要什么结果。用户时区、周期和截止规则只在确需定时任务时写入。
- 技术：已有工作流平台、已发布版本、工作流 ID、作用空间、凭据和具体接口定义。根据真实文档核对字段名、大小写、嵌套及响应，不能猜测通用 API 就可直接套用。
- 功能：逐节点写输入、处理、输出、下一分支；定义任务标识、等待／运行／成功／失败状态。异步接口给出任务提交与结果获取方式，收到任务 ID 不等于业务已完成。
- 重复控制：说明同一触发怎样识别；数据写入、付费请求、邮件等有副作用动作，要定义去重或幂等方式。
- 异常：无副作用的可重试步骤采用有上限策略；外部结果不明时先查询执行状态，不盲目重发。不支持查询或去重时，停止并报告待核对。多步部分成功要说明哪些已完成、哪些可恢复，不假设所有外部动作都可回滚。
- 可观察性：记录执行标识、节点、状态和错误，敏感字段脱敏。通知什么人以及通知条件必须来自用户范围，不默认向他人发送消息。
- 验收：跑通一份真实字段映射；覆盖重复触发、中途超时、空输出、任务仍处理中、部分成功后恢复；有外部副作用时优先模拟／dry-run，并明确实际执行范围。

## 场景特有检查

输出是图片 URL、JSON 字符串还是异步任务，要按实际返回解析；页面有输入不等于参数传入，接口成功不等于最后动作成功。运行日志应足以确定是否可以重试。部署产品的自动化行为需求不等于本次助手已获权执行。
