# 界面设计与复刻专项

## 识别任务

区分从零设计、基于参考借鉴、按设计稿还原、修改已有页面。用户仅给风格参考时，不将参考站的业务、账户或付费功能一并搬入。

有可访问参考时先查看相关页面与状态；缺参考图或无法访问时准确说明缺口。不能声称已观察未打开的页面，也不能虚构测量尺寸。

## 关键规则

- 目标：页面服务什么任务；是验证交互，还是追求视觉一致性。
- 视觉：按区域列页面结构、主次信息和参考部位；明确提供的素材、字体、图标以及可替代项。给关键状态：默认、悬停、选中、禁用、加载、空态和出错，实际不涉及的省略。
- 技术：现有组件库、设计 token、框架与资源目录优先。没有设计系统的新项目，规定少量一致规则，不强行引入依赖。
- 功能：说明按钮、筛选、弹窗、导航和表单如何反应；“看起来能点”与“已接后端”分开。
- 约束：哪些仅外观改动，哪些行为必须保留；参考内容能否直接使用、缺素材如何处理，不自动下载或替换所有资产。
- 验收：约定目标视口，在同等尺寸比较布局、层级、行文、关键间距；检查溢出、文字遮挡、焦点与实际交互。视觉还原任务应要求渲染截图核对，而非只检索 CSS 数值。

## 取舍

不要把全部样式都压成模糊形容词，也不要在没有设计依据时假装每个像素已确认。已有页面的小改动只需定位区域、期望差异和保留状态，不扩大为整站重设计。
