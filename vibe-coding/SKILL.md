# Vibe Coding

## Purpose

把日常语言中的产品想法整理为可实现、可验收的任务，按已有信息进入合适步骤。

## 1. 引导关键决定

已有材料先提取目标、核心动作、范围和已确认选择。分清三种未知：**用户决定**（用途、玩法、业务取舍）由用户选择或明确委托；**可查事实**（工程、接口、现有规范）自行核实；**工程细节**采用合适默认值。

是否"方向模糊"只看目标和核心动作是否已给出，不看细节是否齐全。用户说"接口还没选""没有文档""技术你定"，是把接入留待核实或授权自行决定，不算信息缺口。本轮只要提示词时，把接口字段、鉴权与刷新限制列为"接入前需查实际文档核实"的待办，照已知需求直接交付，不回头索取接口名称或文档。本轮要求实际实现时则不同：缺少必要接口、凭据或会改变结果的业务决定时，仍应向用户核实或询问，不能一律当作待办跳过；先把不依赖这些信息的部分推进，并明确列出所缺条件。

方向模糊时读取 [guided-dialogue.md](references/guided-dialogue.md)，优先问一个影响方案的问题。信息充分时直接成文；获委托的选择标为建议。修订只重开受影响的问题，保留其他决定。

讨论“如果我说……会怎样”时，给示例回复即可。它不代表用户已经提出那个项目。

## 2. 形成可执行任务

当目标、主要操作和本轮边界足够明确，能给出具体验收例子时，就可以交付任务。用户要开发提示词时读取 [development-prompt.md](references/development-prompt.md) 并成文；已要求实现时用简短任务说明直接进入执行参考，无需先输出整份提示词。

消解影响结果的歧义：输入、状态变化、存储、成功与失败反馈。复杂需求按可验证的用户路径拆分，按下表补本轮涉及的机制。

区分已确认要求、建议默认值与待核实事实。默认给简版，普通实现细节授权执行者处理；用户限定长度或只改一段时遵守该范围。读取参考后仍以本轮请求为准；需求充分就交付，不要求重述或再次确认生成。

## 3. 按本轮要求交付

- **只要需求或提示词**：交付具体指令和验收条件，到此结束。
- **明确要求实现／在既有 Vibe Coding 项目中续做**：读取 [execution-loop.md](references/execution-loop.md)，继续已授权的实现、验证与调试，不停在提示词阶段。普通独立修复或评审由相应工作方式处理，无需套入本技能访谈。
- **需要恢复或交接**：读取 [project-memory.md](references/project-memory.md)，沿用项目记录保存必要决定和下一步。

## Examples

模糊想法先引导关键选择：

```text
用户：我想做个小游戏，但不知道怎么描述。
助手：你希望玩家主要享受怎样的体验？可以说一个喜欢的游戏，或描述你希望玩家反复做的动作。
```

本轮只要提示词、需求已给足时直接交付，即使接口或资料尚缺也不倒退回索取任务（实际实现缺必要接口/凭据/业务决定时仍应核实或询问，见第1节）：

```text
用户：整理一段公交看板提示词，只要提示词。收藏线路、看到站时间、看更新时间、断网看上次结果。接口没选、没有文档，别问我接口叫什么。
助手：直接输出提示词，功能按已给的四项写；接口字段、鉴权与刷新限制写为"接入前需查实际文档核实"，用可替换适配层或标注的模拟数据推进界面，不追问接口名称，不把待核实内容写成事实，不输出代码。
```

完整开发提示词示例位于主流程中的成文参考，按实际项目替换。

## Prerequisites

目标宿主为Codex，需能读取参考文件。技能无额外依赖或凭据；项目运行与接入条件在实施时核实。

## Limitations

AI编程不要求产品接模型，实现不自动包含发布。按本轮授权执行；示例与静态检查不能证明真实业务正确。

## Troubleshooting

处理错误与验证缺口（error / validation）：目标不明则问关键选择；只写提示词而无法读工程时，将调查交给执行者。实现缺必要条件时，继续独立可验证部分，列明缺口和未验证项。
